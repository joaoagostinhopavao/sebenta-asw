A.1 Introduction

This appendix gathers, into complete, self-contained files, the code presented piece by piece in Chapter 2. Each block below is an independent .html file, ready to copy into an editor (VSCode or WebStorm) and open directly in the browser, with no installation or server configuration required: Bootstrap is loaded via CDN, and the data shown is fixed directly in the HTML.

This code serves two purposes:

  • In class, as an immediate demonstration: copy it, open it in the browser, and have a small, working Web site to navigate right away
  • In the practical LABs (see Appendix D onward), as boilerplate: the starting point to which the JavaScript needed to consume the REST API is added, without rewriting HTML from scratch

The four files share the same navigation bar and must be saved in the same folder, so that the links between them work: index.html, login.html, capital.html and paises-editar.html.

A note on the visible text in this appendix’s code

The on-screen text inside the four HTML files below (navigation labels, headings, form fields, button captions) is left in Portuguese, exactly as in the Portuguese edition. These are the same literal files, reused verbatim by the practical LABs later in the book (Appendix D onward), and by the screenshots in Chapter 2 — keeping the text identical keeps code and screenshots consistent across both editions.

A.2 Initial Project Structure

Before copying the code, the folder structure that will accompany the project throughout the course is created — from the static files in this appendix to the JavaScript front-office the practical LABs will add to them:

  1. Create a project folder (for example, world-capitals/)
  2. Inside it, place the four .html files from this appendix
  3. Create three subfolders, still empty: css/, js/ and assets/
world-capitals/
├── index.html
├── login.html
├── capital.html
├── paises-editar.html
├── css/
├── js/
└── assets/
  • css/: holds style sheets linked to the html pages. It can also hold adjustments to the Bootstrap loaded via CDN, for instance a custom.css with visual tweaks specific to this application. A single style sheet can be used for all the pages, or each page can have its own.
  • js/: for the JavaScript files. It stays empty for now; this is where, in the practical LABs, the fetch() code that connects these pages to the REST API will go
  • assets/: images, icons, or other static files the application may need

This structure is not required by the browser: a single, isolated .html file, opened directly, already works, as can be confirmed in the following sections. It is, however, the organisation that any real Web project ends up adopting, and it is worth keeping in mind from the start.
