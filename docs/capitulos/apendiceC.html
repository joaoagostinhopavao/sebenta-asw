C.1 Introdução

Este apêndice reúne, num único sítio, todas as ferramentas necessárias ao longo desta UC, com as respetivas ligações de instalação, documentação oficial e alternativas possíveis.

As instruções e ligações abaixo aplicam-se a macOS, Windows e Linux por igual — todas as ferramentas listadas têm versão para os três sistemas. Onde um passo depender do sistema operativo, isso é assinalado explicitamente.

C.2 As Ferramentas desta UC

JDK — Java Development Kit
A linguagem Java e as ferramentas para a compilar e correr — a base de tudo o resto. Recomenda-se a distribuição Eclipse Temurin, gratuita, de código aberto e mantida pela Eclipse Adoptium Working Group, disponível para os três sistemas operativos. Alternativa: o Oracle JDK, oficial da Oracle, com licença diferente. Ajuda: documentação oficial em https://docs.oracle.com/en/java/; para dúvidas concretas, a tag java no Stack Overflow é o primeiro sítio a consultar.
Apache Tomcat
O Servlet Container usado ao longo de toda a UC (ver Capítulo 4), para instalar do lado do servidor. Disponível em https://tomcat.apache.org/. Alternativas existem (Jetty, ou um servidor de aplicações completo como o WildFly, já referido no Capítulo 4), mas não são usadas nesta UC. Ajuda: documentação oficial em https://tomcat.apache.org/tomcat-10.1-doc/; a tag tomcat no Stack Overflow para dúvidas concretas.
Eclipse IDE for Enterprise Java and Web Developers
O ambiente de desenvolvimento (IDE) usado para o código do lado do servidor (Servlets, Filtros, JSP), com suporte integrado para projetos Jakarta EE e para instalar e gerir o Tomcat diretamente a partir do próprio Eclipse. Descarrega-se em https://www.eclipse.org/downloads/packages/ (escolher exatamente o pacote “Enterprise Java and Web Developers”, não o pacote genérico “Eclipse IDE for Java Developers”, que não inclui as ferramentas de projeto Web). Alternativa: IntelliJ IDEA (a edição Ultimate, paga — mas gratuita para estudantes mediante registo — inclui suporte Jakarta EE equivalente; a edição Community, gratuita, não inclui). Ajuda: Fórum da comunidade Eclipse; a tag eclipse no Stack Overflow.
VSCode ou WebStorm
Um editor mais leve, usado para o código do lado do cliente (HTML, CSS, JavaScript, ver Capítulo 2 e Capítulo 8) — não precisa de nenhum dos dois suportes específicos de Java EE do Eclipse. O VSCode é gratuito e multiplataforma; o WebStorm é pago (gratuito para estudantes mediante registo), mais especializado em JavaScript. Ajuda: documentação oficial em https://code.visualstudio.com/docs (VSCode) ou https://www.jetbrains.com/webstorm/documentation/ (WebStorm).
Um browser moderno, com ferramentas de programador
Chrome, Firefox e Edge servem igualmente bem; o importante é saber abrir as suas ferramentas de programador (DevTools, tecla F12 ou Cmd+Option+I no Mac), usadas ao longo da UC para inspecionar pedidos de rede e depurar JavaScript (ver Capítulo 8). Ajuda: https://developer.chrome.com/docs/devtools/ (Chrome) ou https://firefox-source-docs.mozilla.org/devtools-user/ (Firefox).
Um cliente REST
Uma ferramenta para construir pedidos HTTP à mão (GET, POST, PUT, DELETE, com cabeçalhos e corpo à escolha), útil para testar diretamente uma API REST (ver Capítulo 7) sem depender de nenhum front-office já feito. Um simples GET pode sempre testar-se diretamente no browser, mas POST, PUT e DELETE já não. O Postman é o mais conhecido; o Insomnia é uma alternativa mais leve; quem preferir a linha de comandos pode usar o curl, já incluído por omissão em macOS, em Linux, e em Windows 10 e posterior.
MySQL ou MariaDB
O sistema de gestão de base de dados relacional usado a partir do LAB4 (Apêndice G), quando os dados fixos usados nos LABs anteriores são substituídos por dados reais, acedidos através de JDBC. O MySQL Community Server é a edição gratuita e de código aberto do MySQL; o MariaDB Server é uma alternativa também gratuita e de código aberto, diretamente compatível (mesmo protocolo de rede, mesmo driver JDBC) — qualquer um dos dois serve para esta UC. Para criar e gerir as tabelas sem depender só da linha de comandos, é útil instalar também um cliente gráfico, como o MySQL Workbench ou o DBeaver (multiplataforma, compatível com MySQL e MariaDB). Ajuda: documentação oficial em https://dev.mysql.com/doc/ (MySQL) ou https://mariadb.com/kb/en/documentation/ (MariaDB); as tags mysql e mariadb no Stack Overflow para dúvidas concretas.

C.3 Ferramentas Obrigatórias

Da lista anterior, o que é, de facto, indispensável nesta UC:

Ferramenta Versão mínima Nota
JDK 17 (LTS) Exigido pelo Tomcat 10.1 (ver abaixo)
Apache Tomcat 10.1.x Não usar a série 9.x: o código desta UC usa o pacote jakarta.servlet.* (ver Capítulo 6), que só existe a partir do Tomcat 10
Eclipse IDE for Enterprise Java and Web Developers Qualquer versão atual Ou o equivalente IntelliJ IDEA Ultimate
VSCode ou WebStorm Qualquer versão atual Para o código do lado do cliente
Um browser moderno Qualquer versão atual Com DevTools
MySQL ou MariaDB Qualquer versão atual Só necessário a partir do LAB4 (Apêndice G)

Um cliente REST (Postman, Insomnia, ou curl) é recomendado, mas não estritamente obrigatório: os primeiros LABs podem testar-se com formulários HTML simples (ver Capítulo 3), sem qualquer cliente dedicado.

C.4 Confirmar a Instalação

Antes de avançar para qualquer LAB, vale a pena confirmar que cada ferramenta está corretamente instalada:

  • JDK: num terminal, java -version deve devolver o número de versão instalado, sem nenhum erro
  • Apache Tomcat: arrancar o Tomcat e visitar http://localhost:8080 num browser deve mostrar a página de boas-vindas por omissão do próprio Tomcat — não é preciso, nem se espera, nenhum código próprio instalado ainda
  • Eclipse: deve abrir sem erros, e o menu de criação de projeto deve incluir a opção “Dynamic Web Project” — sinal de que o suporte Jakarta EE está corretamente instalado
  • VSCode ou WebStorm: deve abrir sem erros; criar um ficheiro .html qualquer e abri-lo diretamente no browser confirma que o essencial já funciona, sem precisar de nenhum servidor
  • MySQL ou MariaDB: arrancar o servidor e ligar-se a ele — por linha de comandos (mysql -u root -p) ou através do cliente gráfico escolhido — deve funcionar sem erros; não é preciso ainda nenhuma base de dados própria criada, só confirmar que o servidor responde
