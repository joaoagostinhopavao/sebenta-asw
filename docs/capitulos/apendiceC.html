C.1 Introdução

Este apêndice reúne, em ficheiros completos e autónomos, o código apresentado por partes no Capítulo 2. Cada bloco abaixo é um ficheiro .html independente, pronto a copiar para um editor (VSCode ou WebStorm) e a abrir diretamente no browser, sem qualquer instalação ou configuração de servidor: o Bootstrap é carregado por CDN, e os dados apresentados estão fixos no próprio HTML.

Este código serve dois propósitos:

  • Em aula, como demonstração imediata: copiar, abrir no browser, e ter desde logo um pequeno sítio Web funcional a navegar
  • Nos LABs práticos (Apêndice B), como boilerplate: o ponto de partida ao qual se acrescenta o JavaScript necessário para consumir a API REST, sem reescrever HTML de raiz

Os quatro ficheiros partilham a mesma barra de navegação e devem ser guardados na mesma pasta, para que as ligações entre eles funcionem: index.html, login.html, capital.html e paises-editar.html.

C.2 Estrutura Inicial do Projeto

Antes de copiar o código, cria-se a estrutura de pastas que vai acompanhar o projeto ao longo de toda a UC, dos ficheiros estáticos deste apêndice até ao front-office em JavaScript que os LABs práticos lhe vão acrescentar:

  1. Criar uma pasta de projeto (por exemplo, world-capitals/)
  2. Dentro dela, colocar os quatro ficheiros .html deste apêndice
  3. Criar três subpastas, ainda vazias: css/, js/ e assets/
world-capitals/
├── index.html
├── login.html
├── capital.html
├── paises-editar.html
├── css/
├── js/
└── assets/
  • css/: guarda folhas de estilo ligadas às páginas html. Pode também conter ajustes ao Bootstrap carregado por CDN, por exemplo um custom.css com ajustes visuais específicos desta aplicação. Um só ficheiro de estilos pode ser usado para todas as páginas, ou cada página pode ter o seu.
  • js/: para guardar os ficheiros javascript. Fica vazia por agora; é aqui que, nos LABs práticos, vai entrar o código fetch() que liga estas páginas à API REST
  • assets/: imagens, ícones ou outros ficheiros estáticos de que a aplicação venha a precisar

Esta estrutura não é exigida pelo browser: um ficheiro .html isolado, aberto diretamente, já funciona, como se pode confirmar nas secções seguintes. É, no entanto, a organização que qualquer projeto Web real acaba por adotar, e vale a pena te-lo em consideração desde já.
